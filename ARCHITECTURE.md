# Серверный адаптер Fotli

Адаптер запускается в Phusion Passenger и связывает собранный vinext-фронтенд с облачным API.

## HTTP-маршруты

- `GET` / `HEAD` для файлов из `dist/client`: раздача статики с проверкой пути.
- `/api/*`: проксирование к API Gateway или прямой вызов Cloud Functions.
- `POST /tg-bot-relay`: релей вызовов Telegram Bot API с проверкой секрета.
- Остальные запросы: рендер через `dist/server/index.js`; для клиентских маршрутов предусмотрен SPA fallback.

## Два транспорта API

Если `API_FUNCTION_ENDPOINT` пуст, используется обычный HTTP-прокси через `API_UPSTREAM`. Если задан адрес функции с `integration=raw`, исходный запрос преобразуется в событие функции: метод, путь, query, заголовки, cookies, тело в Base64. Ответ функции преобразуется в HTTP со статусом, заголовками и декодированным телом.

Важно сохранять `Set-Cookie` и `Location`: иначе переход к провайдеру входа может работать, а сессия после callback — нет. Транспорт поддерживает cookies в `headers`, `multiValueHeaders` и `cookies` ответа. Заголовки длины, сжатия и hop-by-hop заголовки не копируются в ответ после преобразования тела.

Официальное описание прямого вызова: [Yandex Cloud Functions — вызов функции](https://yandex.cloud/ru/docs/functions/concepts/function-invoke).

## Проверки

`npm test` проверяет преобразование запросов и ответов с подставным `fetch`, без секретов и обращений к рабочим сервисам.

На рабочем сайте после переключения отдельно проверены:

- список провайдеров авторизации: HTTP 200, Telegram и Яндекс включены;
- `/api/me` без сессии: корректный анонимный ответ;
- начало Яндекс OAuth: HTTP 302 на провайдера и callback на домене сайта;
- начало входа через Telegram: успешная выдача запроса на вход;
- webhook бота направлен на домен сайта;
- активные кнопки в браузере и успешный вход, подтверждённый владельцем.

Полноценный сбой Cloud Functions или YDB этот обход не устраняет. Платежи, генерация и скачивание файлов не проверялись в ходе восстановления входа.
